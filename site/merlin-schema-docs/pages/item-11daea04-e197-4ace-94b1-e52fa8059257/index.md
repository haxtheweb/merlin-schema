Event contract
--------------

When a result row is selected, `super-daemon-row.selected()` always dispatches a `super-daemon-row-selected` event (with `detail` = the row element), then dispatches a `CustomEvent` named `option.eventName` with `detail` set to `option.value`. For any `eventName` other than `super-daemon-run-program`, it also dispatches `super-daemon-close` to close the palette. Program selections keep the palette open so the user can continue interacting.

The `super-daemon` singleton listens for these events globally and routes them:

<a11y-collapse heading-button="heading-button"><h2 slot="heading">eventName routing table</h2><div slot="content"><ul><li><strong>super-daemon-element-method</strong> — Calls <code>value.target[value.method](...value.args)</code>. Closes palette.</li><li><strong>super-daemon-element-click</strong> — Dispatches a synthetic <code>MouseEvent("click")</code> on <code>value.target</code>. Closes palette.</li><li><strong>super-daemon-run-program</strong> — Hands <code>value</code> to <code>runProgram()</code> — enters program mode. Does <em>not</em> close palette.</li><li><strong>hax-super-daemon-insert-tag</strong> — HAXStore inserts a block: fills a waiting program target with <code>properties.src/source/href</code>, otherwise inserts through the tray (<code>value</code>: <code>{ value: tag, eventName: "insert-tag", demoSchema: true }</code> or <code>{ properties, content }</code>). Closes palette.</li><li><strong>execute-keyboard-shortcut</strong> — <code>haxcms-site-editor-ui</code> resolves <code>value.shortcutId</code> in <code>KeyboardShortcutManager</code> and runs it. Closes palette.</li><li><strong>disabled</strong> — No-op. Used for informational rows like "No active page found". Closes palette.</li><li><strong>super-daemon-noop</strong> — No-op instruction row (no listener). Closes palette.</li><li><strong>anything else</strong> — Dispatched as a plain <code>CustomEvent</code>; you need your own listener. Closes palette.</li></ul></div></a11y-collapse>

Other events the singleton listens for (dispatch these to drive Merlin from code):

<a11y-collapse heading-button="heading-button"><h2 slot="heading">Other listened events</h2><div slot="content"><ul><li><strong>super-daemon-define-option</strong> — <code>detail</code> is treated as an Option and registered via <code>defineOption()</code>.</li><li><strong>super-daemon-run-program</strong> — <code>detail</code> (<code>{ program, context, name, placeholder, values }</code>) launches a program.</li><li><strong>super-daemon-element-method</strong> — <code>detail</code> (<code>{ target, method, args }</code>) invokes a method on a target.</li><li><strong>super-daemon-element-click</strong> — <code>detail</code> (<code>{ target }</code>) clicks a target.</li><li><strong>super-daemon-close</strong> — Closes the palette and resets state.</li><li><strong>super-daemon-program-enter</strong> — <code>detail</code> (<code>{ programName, input }</code>) handles Enter pressed with no filtered results (used by the create-page program).</li><li><strong>super-daemon-voice-command</strong> — <code>detail</code> (<code>{ command, callback, context }</code>) registers a voice command.</li></ul></div></a11y-collapse>

Context system
--------------

Every Option declares a `context` — a string or array of strings that determines when it is visible. The singleton tracks an active `commandContext` (a single string) and a `context` array (the set of contexts the current page/app state provides). An option appears only when its `context` intersects the active set.

<a11y-collapse heading-button="heading-button"><h2 slot="heading">Context values</h2><div slot="content"><ul><li><strong>*</strong> — Global — always available (the default when <code>context</code> is omitted).</li><li><strong>CMS</strong> — Available while in the HAXcms site-editor context.</li><li><strong>HAX</strong> — Available while in the HAX body editor (authoring) context.</li><li><strong>admin</strong> — Available for admin/site-settings operations.</li><li><strong>logged-in</strong> — Available only when the user is authenticated.</li><li><strong>&gt;</strong> — Developer mode — a special context entered by typing <code>&gt;</code> in the palette.</li></ul></div></a11y-collapse>

The user switches the active `commandContext` by typing a prefix character (`/`, `*`, or `>`) into the search input, or via voice ("run program" → `/`, "developer mode" → `>`). When `commandContext` is `"*"` (global browse), options are filtered against the page's `context` array; when it is a specific value, only options whose `context` includes that value are shown.
